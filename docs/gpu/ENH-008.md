# ENH-008 — Démuxage FFmpeg et décodage NVDEC : note technique

Statut : note de planning du Sprint 1 (gpu-engineer, 2026-10-21), **implémentée** sur `feature/ENH-008-demux-nvdec` (§ 9 : réalisation, écarts, mesures). Références : `docs/architecture/index.md` (ADR-040, 045, 047, 049) et `docs/gpu/pipeline-conception.md` (§ 3.1-3.5), `docs/gpu/spike-phase3.md` § P3.7 (NVDEC mesuré avec `ffmpeg.exe`), `docs/security/threat-model.md` (SEC-08, SEC-13), story ENH-008 de `docs/stories/ENH-008.md`.
**[H]** = hypothèse à mesurer ; **[M]** = mesuré.

## 1. Approche

- **Démux** : libavformat sur un `AVIOContext` maison (ADR-049). Le fichier est ouvert par `CreateFileW` sur la forme étendue du chemin (`std::filesystem::absolute`, préfixe `\\?\` ou `\\?\UNC\`), `GENERIC_READ`, `FILE_SHARE_READ`, `FILE_FLAG_SEQUENTIAL_SCAN`. Rappels lecture / déplacement (y compris `AVSEEK_SIZE`) sur le `HANDLE`. `av_probe_input_buffer2` (format sondé, puis liste blanche § 9.2) puis `avformat_open_input(&ctx, "", format_sondé, &opts)` avec `ctx->pb` posé et `AVFMT_FLAG_CUSTOM_IO` (`libavformat/avformat.h` l. 1424). **Aucun chemin texte n'est donné à FFmpeg.**
- **Ouvertures secondaires interdites** : `ctx->io_open` remplacé par un rappel qui renvoie `AVERROR(EPERM)` (l. 1865 ; concerne HLS, `concat`, références externes MOV) ; `protocol_whitelist=file` en défense en profondeur. **Réalisé** : liste blanche de démuxeurs vérifiée après `av_probe_input_buffer2`, liste noire en second filet (§ 9.2).
- **Décodage** : libavcodec avec hwaccel CUDA (ADR-040). Le contexte matériel FFmpeg **réutilise notre contexte CUDA primaire** : `av_hwdevice_ctx_alloc(AV_HWDEVICE_TYPE_CUDA)`, `AVCUDADeviceContext::cuda_ctx` = notre contexte, `stream` = flux `S_dec`, puis `av_hwdevice_ctx_init` (FFmpeg ne libère pas un contexte qu'il n'a pas créé). **Réalisé** avec l'API runtime (`cudart` statique, contexte primaire ; `cuCtxGetCurrent` par `cudaGetDriverEntryPointByVersion`), voir § 9.2. Rappel `get_format` : choisit `AV_PIX_FMT_CUDA` s'il est proposé, sinon un format logiciel. `extra_hw_frames = 4`.
- **Choix explicite du décodeur natif** : la build BtbN contient `libdav1d`, qui est préféré pour l'AV1 par `avcodec_find_decoder` mais **n'a pas de hwaccel**. On prend donc le décodeur natif par son nom (`av1`, `h264`, `hevc`, `vp9`, `mpeg2video`…) quand NVDEC le gère, et `libdav1d` seulement en repli logiciel. Fonction pure `selectDecoder(codec_id, profil, bits, chroma) → {nom, chemin}` testée en CI.
- **Sortie** : surfaces NV12 (8 bits) ou P010 (10 bits, et 12 bits ramenés à 10) **en mémoire GPU**. Copie GPU→GPU asynchrone (`cudaMemcpy2DAsync` sur `S_dec`) de la surface FFmpeg vers notre `DevicePool` (8 surfaces à pas `cudaMallocPitch`, allouées à la première image de chaque format) puis `av_frame_unref` : le pool FFmpeg est libéré tout de suite, la back-pressure se fait sur notre pool. Chaque `VideoFrame` porte un événement CUDA (`FrameBuffer::readyEvent`) (aucune synchronisation CPU dans la boucle, ADR-045).
- **Repli logiciel** (codec ou profil non gérés par NVDEC, ou échec d'init hwaccel) : même `AVCodecContext` sans `hw_device_ctx`, conversion `libswscale` vers NV12 / P010 **directement dans un tampon épinglé** (`PinnedPool` : `cudaHostAlloc`, 3 tampons tournants), envoi `cudaMemcpy2DAsync`. Une ligne de journal (`warn`, code `DecoderFallback`, codec + raison). Les sources 4:2:2 / 4:4:4 sont ramenées en 4:2:0 (perte de chrominance documentée).
- **SEC-13** : `enh::pipeline::checkedMul` / `checkedAdd` (`std::size_t`, renvoient `Expected`) ; dimensions bornées dès l'ouverture (1 ≤ l, h ≤ 8192, `av_image_check_size2`), avant toute allocation ; pas de ligne et décalages de plans calculés avec ces fonctions seulement.

## 2. Classes RAII (une ressource C = une classe, `enh::Expected` pour les erreurs)

| Classe | Création → libération | Remarque |
|---|---|---|
| `Win32File` | `CreateFileW` → `CloseHandle` | erreurs Win32 → `SourceMissing` / `SourceUnreadable` (ADR-049) |
| `AvioReader` | `av_malloc` + `avio_alloc_context` → `av_freep(&pb->buffer)` + `avio_context_free` | libère `pb->buffer` (FFmpeg peut l'avoir réalloué), pas le pointeur d'origine |
| `AvInput` | `avformat_alloc_context` + `avformat_open_input` → `avformat_close_input` | détient `AvioReader` et `Win32File` (ordre de destruction par l'ordre des membres) |
| `AvCodecCtx` | `avcodec_alloc_context3` → `avcodec_free_context` | |
| `AvBuffer` | `av_hwdevice_ctx_alloc` / `av_buffer_ref` → `av_buffer_unref` | contexte matériel CUDA |
| `AvPacket`, `AvFrame` | `av_packet_alloc` / `av_frame_alloc` → `av_packet_free` / `av_frame_free` | `std::unique_ptr` + suppresseur |
| `CudaContext`, `CudaStream`, `CudaEvent` | contexte primaire de `cudart` (non libéré, § 9.2) ; `cudaStreamCreateWithFlags` / `cudaEventCreateWithFlags` → `cudaStreamDestroy` / `cudaEventDestroy` (`CudaStream`, `CudaEvent`, `src/pipeline/gpu/nvdec/cuda_raii.hpp`) | partagés avec les étages suivants |
| `DevicePool`, `DeviceFrameBuffer` (`DeviceMemory`) | `cudaMallocPitch` → `cudaFree` ; la surface revient au pool dans son destructeur | aucune allocation dans la boucle |
| `PinnedPool`, `PinnedFrameBuffer` (`PinnedMemory`) | `cudaHostAlloc` → `cudaFreeHost` | repli logiciel seulement |
| `SwsCtx` | `sws_getContext` → `sws_freeContext` | repli logiciel |

Tous les codes retour (`int` FFmpeg, `CUresult`, `GetLastError`) passent par `check(...)` → `PipelineError` (code, code natif, `av_strerror` / `cuGetErrorString`, `std::source_location`).

### 9.2 Écarts à la note (à relire par le reviewer)

- **API CUDA runtime** (`cudart` statique) au lieu de l'API pilote `cuDevicePrimaryCtx*` : même contexte primaire, et ADR-048 respecté (aucune liaison à `cuda.lib`, `nvcuda.dll` chargée à la demande). `cuCtxGetCurrent` est obtenu par `cudaGetDriverEntryPointByVersion` pour le donner à FFmpeg. Test : `cudaContext() == ffmpegCudaContext()`.
- **Démuxeurs : liste blanche après sondage** (revue C1, cycle 2) : `mov`/`mp4`, `matroska`/`webm`, `mpegts`, `avi`, et pour ENH-008b `mpeg`, `asf`, `flv`, `mxf`, `ivf`, `obu`, `h264`, `hevc`, `mpegvideo`, `m4v` ; tout autre démuxeur → `UnsupportedFormat` + journal `DemuxerRefused`. Liste noire en second filet : `concat`, `hls`, `dash`, `imf`, `image2`, `sdp`, `rtp`, `rtsp`, `sap`, `ffmetadata`, `tee`, `vobsub`, `avisynth`, `vapoursynth`, `dvdvideo`. Origine : constaté pendant les tests, `concat` ouvre ses fichiers par un contexte imbriqué **sans passer par notre `io_open`** (seul `protocol_whitelist` s'applique). On sonde donc le format (`av_probe_input_buffer2`) avant `avformat_open_input` et on refuse ces démuxeurs (`UnsupportedFormat`, journal `DemuxerRefused`). HLS n'est de toute façon pas reconnu sans extension (aucun nom de fichier n'est donné à FFmpeg). Point pour secdevops.
- `enh_pipeline_ffmpeg` lie `enh_pipeline_core` : consigné dans l'**amendement 1 d'ADR-037**.
- Interfaces d'étage dans une cible INTERFACE dédiée **`enh_pipeline_stage`** (`src/pipeline/stage/include/`), que l'application ne lie pas (amendement 1 d'ADR-037).
- **Couleur du chemin logiciel** (revue C2) : `planSoftwareColor` rend la conversion libswscale explicite (`sws_setColorspaceDetails`) : YUV → YUV sans changement de matrice ni de plage (les `yuvj*` restent en plage pleine, étiquette `Full`) ; RVB → YUV en BT.709 plage limitée (étiquette mise à jour). Tests : MJPEG `yuvj420p` et FFV1 `bgr0`.
- Noms en `camelBack` (`checkedMul`) imposés par `.clang-tidy`, au lieu de `checked_mul`.
- Mesures par un test GoogleTest chronométré (`enhance-bench --stage decode` arrive avec ENH-047).
- Comptage « = ffprobe » : `ffprobe.exe` de la même build (`third_party/ffmpeg/lgpl-shared/bin`), appelé par les tests unitaires (clips générés) et GPU (corpus).

### 9.4 Points ouverts

- **Livraison (ENH-048)** : le repli logiciel AV1 utilise `libdav1d` (présent dans la build BtbN) ; le FFmpeg vcpkg de livraison doit l'inclure, sinon un AV1 non géré par NVDEC (12 bits, 4:4:4) ne se décode pas.

## À retenir en C++

- **RAII au lieu de `goto cleanup`** : en C, chaque `avformat_open_input` / `cudaMalloc` impose un chemin de nettoyage écrit à la main. Ici `std::unique_ptr<AVFormatContext, FormatInputDeleter>` (ou `DeviceMemory`, `Win32File`) libère tout seul à la sortie de portée, même sur un `return` d'erreur au milieu de la fonction.
- **Ordre des membres = ordre de destruction** : dans `FfmpegDemuxer`, `io_` est déclaré avant `fmt_`, donc détruit après lui ; le contexte FFmpeg est fermé avant l'AVIO qu'il utilise. En C, on écrirait cet ordre à la main dans une fonction `close()`.
- **`std::shared_ptr` pour une durée de vie partagée** : une surface GPU garde son pool en vie ; si le décodeur est détruit avant la dernière image, la mémoire reste valide et revient au pool à la destruction de l'image (en C : compteur de références et `free` manuels, source classique de double libération).
- **Erreurs par valeur (`enh::Expected<T, PipelineError>`)** au lieu d'un `int` de retour + `errno` : l'appelant ne peut pas lire le résultat sans tester la réussite, et l'erreur transporte son code P-08, le code natif (AVERROR, cudaError_t, GetLastError) et l'emplacement.
