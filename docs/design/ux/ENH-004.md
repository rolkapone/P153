# ENH-004 — Squelette Qt Quick et prototype Mica (UX)

Statut : v0.1 (ux-designer), 2026-10-21. Sources : `wireframes.md` W1, `ecrans.md`, `principes.md`, `design-system.md` v1.1 (§6.6 replis), `maquettes/ecran-principal.html`. Aucune conception nouvelle : on prend la coque validée et on en retire tout ce qui demande de la logique.

Parcours concerné : P-01, étapes 1 et 2 seulement (« il lance Enhance, une fenêtre s'ouvre, une ligne discrète indique la carte »). Pas de dépôt, pas de file.

Objectif du squelette : prouver Qt Quick + Mica + verre + HiDPI + accessibilité. L'utilisateur final n'en tire rien d'autre qu'une fenêtre belle et calme.

## 1. Périmètre exact

### Affiché
| Zone | Contenu | Remarque |
|---|---|---|
| Barre de titre | Barre Windows standard (DWM), texte « Enhance », boutons Réduire / Agrandir / Fermer natifs, **sombre** | Pas de barre de titre dessinée à la main : les boutons restent ceux de Windows (snap layouts compris) |
| Fond | Mica (`DWMSBT_MAINWINDOW`) + `windowTint`, ou repli opaque `bgWindow` | Voir §2 |
| Zone centrale | État vide W1, **sans** bouton ni action : illustration (cadre vidéo + flèche), titre, sous-titre | Cadre en pointillés présent (c'est l'identité de l'état vide) mais inerte |
| Contrôle de démonstration | Une capsule de verre « Tester le ressort », en bas de la zone centrale, au-dessus de la barre d'état | Voir §3 |
| Barre d'état | Pastille + « GeForce RTX 5070 · prête » en bas à gauche | Texte fourni par une propriété C++ (valeur fixe, pas de détection) |
| Thème | Sombre par défaut ; bascule clair/sombre en suivant Windows, en direct | Pas de réglage dans l'app |

### Pas encore affiché (ne pas l'ajouter, ne pas le griser)
Bouton « Choisir des fichiers… » (Ctrl+O), roue Réglages (Ctrl+,), panneau Préréglage, barre de verre Préréglage / Démarrer, liste et cartes, feuilles, bandeaux « Rétablir », bandeau de pilote (W1b), glisser-déposer (aucune réaction au survol, aucun curseur « déposer »), détection de la carte, raccourcis hors Ctrl+Q. Raison : un bouton visible qui ne fait rien est pire qu'un bouton absent (principe 2).

Un fichier glissé sur la fenêtre n'est pas accepté : curseur « interdit » de Windows, aucun message (la fonction arrive avec ENH-016).

## 2. États à valider

| État | Ce que l'on voit |

| Démarrage (à froid) | La fenêtre apparaît **déjà peinte** (fond + titre + état vide), centrée, 1100 × 720 px logiques (réduite si l'écran est plus petit). Pas d'écran d'accueil, pas de flash blanc, pas de fenêtre vide qui se remplit. Apparition par fondu 200 ms (instantanée si animations réduites). |
| Sombre | Défaut. Mica sombre + `windowTint`, barre de titre sombre. |
| Clair | Mica clair, barre de titre claire, textes `textPrimary` clair. Mêmes éléments, mêmes positions. |
| Bascule Windows en cours d'exécution | Transition < 300 ms sans clignotement, sans redémarrage ; barre de titre et fond changent ensemble. |
| Transparence Windows désactivée | Pas de Mica : fond opaque `bgWindow` ; le contrôle de verre devient opaque (`surfaceRaised`, ombre e2) ; aucun texte ne change de position. Bascule en direct. |
| Contraste élevé | Couleurs système (fond, texte, sélection) ; cadre de l'état vide en trait plein `WindowText` 2 px ; capsule de verre = bouton opaque avec liseré 2 px, sans reflet ni ombre ; pastille d'état accompagnée du texte (jamais seule). |
| Animations réduites | Fondu d'ouverture et bascule de thème instantanés ; la capsule « Tester le ressort » change seulement de valeur (aucun ressort, aucun reflet qui suit le pointeur). |

Aucun état « en cours », « pause », « erreur » ou « annulé » : il n'existe pas de traitement.

## 3. Contrôle de démonstration

- Capsule de verre « Tester le ressort », centrée horizontalement dans le tiers bas, avec à côté (même ligne) le texte « Essais : 0 ».
- Action : appelle le C++ qui incrémente un compteur ; le `Q_PROPERTY` est relu par le QML (« Essais : 1 », …). C'est le test « une action QML appelle le C++ et une propriété C++ est affichée » exigé par le critère d'acceptation.
- Survol : le reflet suit le pointeur. Pression : la capsule gonfle (1 → 1,03 → 1, ressort). Clavier : Espace ou Entrée déclenchent la même chose.
- Ce contrôle est **provisoire** : il disparaît dès qu'une vraie action en verre existe (ENH-016). Il porte la mention discrète « Démonstration technique » en `textSecondary` sous la capsule, pour que personne ne le prenne pour une fonction.

## 6. Clavier

| Touche | Effet |
|---|---|
| Tab / Maj+Tab | Un seul arrêt interactif : « Tester le ressort ». Tab depuis ce bouton sort vers la barre de titre Windows (pas de piège), puis revient au bouton |
| Focus au démarrage | Sur la fenêtre elle-même, **sans anneau** visible ; le premier Tab met l'anneau sur la capsule |
| Anneau de focus | Visible dès que le focus vient du clavier : ≥ 2 px, contraste ≥ 3:1 avec le fond dans les deux thèmes, suit la forme de capsule, pas d'anneau au clic souris |
| Espace / Entrée | Active la capsule |
| Ctrl+Q | Quitte immédiatement (aucun traitement en cours, donc **aucune feuille**, aucun message) |
| Croix, Alt+F4 | Idem : la fenêtre se ferme et l'application s'arrête. (La règle « la croix réduit » ne vaudra que pendant un traitement, plus tard.) |
| Alt+Espace | Menu système Windows standard, inchangé |
| Win+flèches, snap | Fonctionnent ; le redimensionnement ne descend pas sous 760 × 520 |

## 7. Critères d'acceptation UX (à ajouter à ENH-004, formulés pour le qa-tester)

1. **Premier affichage.** Au lancement à froid, la première image visible contient déjà le fond, le titre « Enhance » et le texte « Déposez vos vidéos ici » ; aucun écran d'accueil, aucun flash blanc ni fenêtre vide (capture vidéo image par image).
2. **Contenu strict.** À l'écran : barre de titre, état vide (titre + sous-titre), capsule « Tester le ressort » avec « Essais : 0 » et « Démonstration technique », barre d'état « GeForce RTX 5070 · prête ». Aucun autre bouton, menu ou texte ; textes identiques à §5, en français.
3. **Dépôt inerte.** Glisser un fichier sur la fenêtre n'ajoute rien, n'affiche aucun message et ne plante pas ; le curseur reste « interdit ».
4. **Thèmes.** Sombre par défaut si Windows est en sombre ; clair si Windows est en clair ; changer le thème de Windows pendant que l'app est ouverte change fenêtre et barre de titre en < 300 ms, sans clignotement ni relance ; contrastes texte ≥ 4,5:1 et capsule / focus ≥ 3:1 dans les deux thèmes (mesure sur capture).
5. **Replis Windows.** Transparence désactivée : fond opaque, capsule opaque, aucune différence de position. Contraste élevé : toutes les couleurs viennent du système, cadre et capsule bordés d'un liseré visible. Animations désactivées : aucune transition de mouvement (ouverture, ressort, reflet).
6. **Mise à l'échelle.** À 100, 125, 150, 175 et 200 % : rien de tronqué ni de superposé, texte et icônes nets (comparaison à l'échelle 1:1 des captures) ; la fenêtre minimale 760 × 520 reste utilisable ; déplacer la fenêtre entre deux moniteurs d'échelles différentes la rend nette en < 1 s.
7. **Clavier seul.** Avec le seul clavier : Tab atteint la capsule avec un anneau visible (≥ 2 px, ≥ 3:1), Espace et Entrée l'activent (« Essais » augmente), Tab ne piège pas le focus, Ctrl+Q ferme l'application sans boîte de dialogue ; la croix aussi.
8. **Narrateur.** L'ordre de lecture et les noms du §5 sont respectés ; la capsule est annoncée comme bouton ; chaque incrément du compteur est annoncé une fois ; l'illustration n'est pas lue.
9. **Fluidité.** Le ressort de la capsule et le fondu d'ouverture tiennent 60 i/s à 100 % et à 200 % (aucune image > 20 ms sur 20 activations rapides) ; au repos, aucune image n'est rendue (pas d'animation en boucle).
10. **Démarrage.** Fenêtre affichée en moins de 2 s à froid (mesure déjà exigée par la story), sans appel réseau.
