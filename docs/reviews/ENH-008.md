### Pour le PO (C++)
- **`noexcept` est une promesse, pas une protection.** Si `std::string` lève `bad_alloc` dans une fonction `noexcept`, le programme s'arrête net. Si l'exception traverse un rappel C (FFmpeg), le comportement est indéfini. D'où la règle : aux frontières avec du C, on attrape tout (`catch (...)`) et on renvoie un code d'erreur C.
- **Ordre des membres = ordre de destruction.** `io_` est déclaré avant `fmt_` : le contexte FFmpeg est donc détruit avant le lecteur AVIO qu'il utilise, sans nettoyage écrit à la main, même sur un `return` au milieu d'`open()`.
