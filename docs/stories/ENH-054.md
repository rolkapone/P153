### ENH-054 — Flux PR, CI renforcée et méthodes de développement  [CI] [Must | 3 pts | voie STANDARD]
En tant que PO, je veux que chaque story passe par une PR vérifiée par la CI, et que les agents suivent des méthodes écrites, afin que les agents ne perdent plus de temps en contrôles manuels et que les défauts de lisibilité soient évités avant la revue.
Cadre : hors sprint, **avant le Sprint 2** (décision n° 35). Décisions liées : n° 33 (flux PR, remplace la n° 32), n° 34 (tests GPU en local, une fois par story). Implémenteurs : devops (volets a et b), reviewer avec les implémenteurs (volet c). Aucun code applicatif.

Critères d'acceptation :

**a. Flux PR**
- [ ] Étant donné `.github/`, quand on ouvre une PR, alors un modèle (`pull_request_template.md`) propose la liste de contrôle de la Definition of Done (critères, CI verte, résultat de `scripts/test-gpu.ps1` pour `[GPU]`/`[ML]`, « À retenir en C++ ») et la ligne `Closes #n`.
- [ ] Deux modèles d'issue existent (story, dette) avec les labels par défaut `story` / `dette`.
- [ ] Une PR d'essai sans `Closes #n` est signalée par la CI ; avec `Closes #n`, l'issue se ferme au merge (vérifié sur ENH-054 elle-même).
- [ ] La branche est supprimée automatiquement après merge (réglage du dépôt vérifié).
- [ ] La carte « Enhance — Sprints » place l'issue de la PR dans la colonne voulue (à revoir / terminé) sans action manuelle ; constat documenté dans `docs/dev/flux-pr.md` (≤ 40 lignes : étapes d'une story, du push au merge).

**b. CI (sans GPU)** — chaque contrôle est prouvé par un cas fautif qui **échoue** (PR d'essai ou test du script), puis par un cas correct qui passe.
- [ ] Messages de commit de la PR : Conventional Commits, ligne `Agent: <rôle>` finale, auteur et committer en `…@users.noreply.github.com`, aucune mention d'outil ni `Co-Authored-By`.
- [ ] Budgets de taille : `ETAT.md` ≤ 8 Ko, fiche de story ≤ 8 Ko, autre doc ≤ 40 Ko ; un fichier trop gros échoue.
- [ ] Liens internes des docs (`docs/**/*.md`) : un lien mort échoue.
- [ ] **ASan** sur les tests du cœur (job dédié, repris d'ENH-049) ; une fuite ou un dépassement injecté échoue.
- [ ] Format, tidy, SAST, tests unitaires et UI, zéro réseau : exécutés par la CI sur chaque PR et exigés pour le merge (protection de `main`) ; les agents ne les relancent plus à la main.
- [ ] Inventaire dans `docs/dev/flux-pr.md` : tout contrôle encore manuel est listé avec la raison (GPU, jugement) ; `scripts/test-gpu.ps1` reste local, une fois par story (n° 34).

**c. Méthodes**
- [ ] `docs/dev/methodes.md` (≤ 60 lignes), écrit par le reviewer avec les implémenteurs, contient : règles de lisibilité et de maintenabilité ; liste des motifs relevés aux cycles 1 du Sprint 1 (action 2 de la rétro, [sprint-1.md](../sprints/sprint-1.md) « Rétro ») ; auto-relecture avant revue (liste courte) ; **un test de cas d'échec par critère mesuré**.
- [ ] `CLAUDE.md` n'est pas modifié par cette story : le guide est référencé dans les PASSATION de l'implémenteur et du reviewer.
